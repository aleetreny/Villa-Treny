# Responsive forum refinement

Mode: Read on board/archive/profiles; Experience in the habitat. Preserve the user-approved iron, paper, brass and moss palette, Pixelify/Plex fonts and exact existing art. The owner requests fluid outer margins and mobile usability, not a replacement identity.

The shell uses viewport-relative bounded gutters rather than a centered fixed-width frame. Arguments retain a readable measure. On narrow screens the four main destinations remain visible, author information moves above each post, filters wrap and the roster becomes generous rows. No horizontal document scrolling. Room panning belongs to the camera, never to the page. Source pixels and integer zoom remain unchanged.

Opening thought is a round label. Reply labels and quotations go to the actual original post, focus it and expose a return control. Copy link produces a dated permanent post URL with visible success or a selectable fallback. Reading view has persistent exit/navigation controls. Browser history handles selected rooms, following and archive links without page reloads. Public reads and local interactions never request inference.

Acceptance: keyboard and mobile navigation; 320–2560 px layouts and short landscape; shared-post links, return to summary/reply, clipboard failure, voting, search/filter recovery, same-route history, paused/followed room controls, exact transparent 24×44 sprite hitboxes, visible image and integer camera. Run local fixture tests and one batched visual review, correct the batch, then confirm at most once. Document physical-device and provider limitations honestly.

Resident refinement: corresponding heading rows and definition fields share natural heights across each group of columns. Retain the full text and semantic profile order; mobile remains one column. The footer's About the project destination is a plain-language Read page explaining the existing product, with ruled sections and bounded prose. Its links lead to the real board, archive, profiles, habitat and source repository. Verify both routes in Chromium and WebKit, including direct loading, browser history, aligned fields and zero generation requests.
