# Bounded structural feedback: released implementation

Status: **deployed as `caf46bd8-1bda-40f6-a1f3-b60dfe420375`**, alongside P7 / SQL11 / society codec 3. [Release validation](release-2026-09-09/retrieval-release-validation.json) records 1,019 application / 355 Worker / 62 Node tests, 21 fresh browser flows and six hosting checks; native post-release review remained blocked by the locked Mac. The [N94 diagnostic](release-2026-09-08/N94-message-length-diagnostic-2026-09-09.json) established a concrete failure: an otherwise parseable message had 695 characters against its issued 300-character limit, while the subsequent retry feedback contained only the generic `invalid_record_choice` code. The earlier request-window correction addressed whether a retry could be dispatched in time; it did not correct long output generation.

The implementation derives optional feedback from a retained private rejection and its exact issued schema. It leaves the rejected response, strict local acceptance, original job, accounting and retry policy unchanged. It neither repairs output nor causes another retry solely to obtain diagnostics. The original Groq request used `strict:false`; this is not presented as a failure of a guaranteed strict decoder.

[`savedStructuralRetryFeedback`](../../workers/habitat-runtime/src/retry-feedback.ts) accepts only supported P6/P7 structural rejection codes and an already retained rejection for that job. It checks contract version, error phase, complete candidate/schema capture, hashes, system binding and original or receipted retry USER binding. Missing, truncated, stale, mismatched, length-finished or unsuitable diagnostic evidence produces no hint. A prior augmented USER must match an existing retry receipt; at most 32 recent receipt rows are inspected.

[`structuralValidationFeedback`](../../workers/habitat-runtime/src/structural-feedback.ts) runs the installed schema compiler against the candidate. It emits at most four unique issues and 600 UTF-8 bytes. Each issue contains only a known schema field path and fixed error vocabulary, optionally a numerical bound or primitive type. The N94-shaped case yields `message.text`, `maxLength`, 300. It does not copy candidate text, unknown property names, enum IDs, schema descriptions, Zod prose or private reference values. Schema and candidate input bounds are 192 KiB and 64 KiB, with bounded traversal.

For unions, it excludes branches contradicted by supplied discriminants and branches requiring strictly more removals of supplied property names. It then reports only constraints shared by every remaining viable branch. It does not infer an intended operation or tell an agent to accept a deal merely because another branch requires one. Ambiguous or unsupported structural cases can therefore return no hint. Domain failures whose candidate satisfies the issued schema also receive no invented structural diagnosis.

Feedback is appended to an already permitted retry's USER text; the immutable SYSTEM and job remain intact. The actual augmented input is metered by the existing route. Private diagnostics remain outside the public observer, and feedback introduces no public raw-response endpoint. Metadata hashes alone do not provide exact replay: reconstruction remains limited to the candidate/schema bytes actually retained, not an absent HTTP envelope.

[Compiler tests](../../workers/habitat-runtime/test/structural-feedback.test.ts) cover actual P6/P7 schemas, message bounds, malformed references, unknown-key privacy, union alternatives, output limits and the historical 600-character draft schema. [Durable retry tests](../../workers/habitat-runtime/test/structural-retry-feedback.test.ts) cover exact bindings, omitted hints on mismatches and the real isolated retry path without external HTTP. This verifies bounded diagnostic behavior, not that any model will correct its next response or improve semantic quality. The [revision 247 status](release-2026-09-09/retrieval-propagated-live-status.json) reports healthy physical/cognitive scheduling; this is not evidence of a corrected model response. The separate [continuity receipt](release-2026-09-09/retrieval-natural-continuity-receipt.json) reproduces SQL11 migration plus H104's natural P7 message across all 26 tables, 1,750→1,761 rows, with exact row IDs/columns and duplicate no-ops. Both strict failures remain: the first post-cut held the old schema, and the later migration-only comparison rejected natural activity. Its zero-HTTP replay wrapped saved output/usage in a synthetic response, not the original wire envelope. H104 used 6,486 input / 111 output Groq120B tokens and made no lookup or document operation; no new research inference was made.

The [predeclared retrieval evaluation](authorized-retrieval-semantic-evaluation-plan-2026-09-09.md) is separate from feedback testing and remains unexecuted. Revision 247's seven drafts are already supplied to their authors; all 25 P6 contexts report zero omitted drafts, so that cut cannot demonstrate recovery of omitted content. Neither the release, its healthy status nor the replay establishes improved semantics.
