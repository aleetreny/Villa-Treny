# Rejected response diagnostics — proposal and implementation checkpoint

The implementation checkpoint below describes the current branch. The original proposal is preserved afterward as historical context. This note does not establish deployment status.

## Implementation checkpoint — 8 September 2026

The bounded private receipt is now implemented in the [provider adapters and shared capture/verification helpers](../../workers/habitat-runtime/src/providers/shared.ts), [router](../../workers/habitat-runtime/src/providers/router.ts) and [private rejection log](../../workers/habitat-runtime/src/rejection-log.ts). No inference was required to implement or verify this patch.

- Each rejected candidate has its own job/attempt/provider/model identity, contract name/version, issued-schema hash, hashes of the actual SYSTEM and USER messages sent by that adapter, selected field/type, source, allowlisted finish reason and HTTP status when available. Actual message hashes include existing adapter additions such as the legacy Qwen schema text and `/no_think`. Prompt text is not copied into the receipt.
- Failures distinguish malformed envelope/content JSON, invalid JSON values or root shape, grouped schema/decode refusal, domain refusal and truncation. Grouped codes such as `invalid_record_choice` use `schema_or_decode`; they do not establish which internal check failed. Unknown callback codes become `domain_validation_failed`, and arbitrary provider messages, headers and unknown metadata keys are excluded.
- The selected candidate is retained before trimming or removing a complete reasoning wrapper, up to **64 KiB of UTF-8 text**. String capture preserves the selected string; a non-string binding value is labelled `binding_serialization`, which is its JSON serialization rather than original HTTP bytes. A prefix ends at a code-point boundary and carries its own hash. The full rendered candidate is also hashed when it fits the separate **4 MiB hashing budget**; otherwise `fullSha256` is explicitly null. The issued schema is stored completely at up to **192 KiB**; larger schemas retain length and a hash where that hashing budget permits. JSON storage overhead is counted separately by the aggregate retention limit.
- `candidate.complete` means that the entire observed candidate or serialization was captured. It does **not** mean generation finished, the response was accepted, or the private domain state can be replayed. In particular, `finish_reason=length` remains rejected even when its observed candidate is completely captured and parses as valid JSON. Successful attempt results gain no diagnostic raw-content field.
- Reported usage is settled once, including invalid and truncated responses; missing usage remains conservative. The synchronous `onAttempt` hook records the rejected primary after quota accounting and before fallback, retaining distinct receipts for both providers. Capture/hash failures are best-effort and do not authorize another request. A failure to persist the underlying attempt/accounting stops fallback; a failure of the optional diagnostic write is contained by its caller. The successful acceptance path gains no diagnostic await.
- Private SQL retention is bounded by **64 receipts**, **16 MiB** of stored diagnostic JSON, and a **seven-day age policy**. Expired receipts are collected on the next attempt write, not by observer reads; expiry does not run a background deletion timer. Accepted outputs and other history are unchanged. Captures are available only through authenticated private recovery; frozen recovery cuts remain consistent when live receipts are pruned. See [recovery handling](../recovery.md). An exported private backup has its own lifecycle; live retention does not erase it.

The [provider diagnostic tests](../../workers/habitat-runtime/test/provider-diagnostics.test.ts) and [rejection-log tests](../../workers/habitat-runtime/test/rejection-log.test.ts) pass **19/19 focused checks** (16 provider-diagnostic cases and three private-log cases). They cover exact candidate/hash capture, Unicode and size bounds, actual adapter message hashes, malformed/root/truncated distinctions, an unknown error code, callback/hash failures, a rejected primary followed by successful fallback, one settlement per real SQL reservation, persistence before fallback, control changes, private retention and recovery. The corresponding complete Worker checkpoint passes **248 tests**. These are isolated fixture checks, not a measurement of live model quality or a claim that every rejected response has been explained.

Limits of this implementation remain explicit: it does not add detailed Zod issue paths, parsed decision-category summaries, the revalidated schema hash, complete validation-state revisions, an HTTP-envelope capture, or a new diagnostic for final revalidation after the router has returned. A retained full output can be checked against its captured issued schema and versioned decoder, but reproducing a domain refusal also requires its exact private state. A partial capture or absent full hash cannot reconstruct missing bytes. No old rejection is backfilled; the lost F58 candidate remains unknown.

## The present evidence gap

[Provider parsers](../../workers/habitat-runtime/src/providers/shared.ts) collapse malformed JSON and wrong root shape into exceptions. [Workers AI](../../workers/habitat-runtime/src/providers/workers-ai.ts) and [Groq](../../workers/habitat-runtime/src/providers/groq.ts) return broad codes such as `invalid_structured_output`, without the selected content's shape or hash. The [router](../../workers/habitat-runtime/src/providers/router.ts) also drops an otherwise parsed payload when the boolean domain callback refuses it. Usage is settled before this validation, which must remain true.

In [processSocietyJob/saveAttempt](../../workers/habitat-runtime/src/habitat-world.ts), one mutable `validationCode` spans the primary and fallback calls; it is not a per-provider diagnosis. The persisted attempt retains code and latency, but not finish reason, response shape or failed-field paths. The [P5 decoder](../../src/lib/habitat/society/ordered-choice.ts) further groups grammar and conversion failures under `invalid_ordered_choice`. These layers explain the missing evidence; they do not explain F58's actual output.

## Smallest useful receipt

Attach a versioned **private receipt to each existing attemptId**, before dropping its candidate or dispatching fallback. Do not overwrite the primary's receipt with the fallback's. Keep successful saved outputs and historical ledgers intact.

| Category | Proposed bounded metadata |
| --- | --- |
| Identity | Diagnostic version, job/attempt ID, provider/model, contract name/version, source or deployment version, issue/receive times. |
| Exact contract | Sent `schemaHash`; SYSTEM and actual USER hashes, including any existing correction suffix. Also record the revalidated schema hash and captured/current world, mind and conversation revisions when applicable. A changed state can invalidate an otherwise well-formed response. |
| Envelope | HTTP status when available; binding versus HTTP source; allowlisted `finish_reason`; selected field (`choices[0].message.content`, `response`, or none); selected value type; complete byte count and hash where available. |
| Shape | Parsed root type, presence of known fields, `turn` type/length, the two item types, and normalized decision category (`no_deal`, proposal type, accept, reject, unknown). Never copy arbitrary field names or values into metadata. Exact offer IDs belong in the private candidate, not the public category. |
| Failure | Separate `transport`, `provider_rejection`, `envelope_json`, `content_json`, `root_shape`, `issued_schema`, `wire_conversion`, `domain_validation`, and `final_revalidation` phases. Store an allowlisted code and at most 8 sanitized issue paths, depth 8, length 120 each; retain an omitted-count indicator. |
| Accounting | Existing reservation and actual usage references, incomplete/unknown status, output maximum, latency. Reasoning tokens remain part of output tokens; no second charge or repricing. |

Examples of sanitized paths are `turn[0].choice`, `turn[1].project.steps[0].verb` and `turn[1].message.close`. Unknown object keys become `*`; invalid values, expected enum contents, Zod exception messages, text excerpts and private reasoning are excluded. Shape and decision categories describe a rejected candidate, **never an accepted action**. Provider finish reasons and error codes also require allowlisting: they are untrusted strings, not safe public text merely because a provider supplied them.

Metadata alone cannot reproduce the rejected output. An optional, explicitly enabled private capture could retain the original candidate without repair or normalization, capped at 64 KiB, and a bounded HTTP envelope where available within the existing 256 KiB Groq response limit. Record `full`, `prefix`, or `not_captured`; only `full` supports an exact output replay. Do not pretend that JSON serialization of a Workers binding object is the original HTTP wire: label its hash scope `binding_serialization`. A response stopped at the size limit has a partial count/hash, not a full-response fingerprint. No credentials, request Authorization headers or provider error messages should enter a public endpoint. A bounded starting policy would retain at most 64 captured attempts for seven days, with a 16 MiB aggregate cap; whichever limit is reached first expires only these optional captures. Persist capture expiry/status so later analysis knows the bytes are gone. Existing accepted outputs and archived evidence are unaffected. Include captures in authenticated recovery and integrity checks only under the same private handling: backups stay outside Git/public artifacts with restricted access and an explicit lifecycle. Live TTL does not erase exported backups. Old rows remain `not_captured`, with no reconstructed response. These are proposed limits, not an enabled retention policy.

## Public boundary and diagnostic behavior

The observer needs only safe stage/code counts, protocol/provider, and existing usage/health summaries. Keep candidate text, schemas, exact IDs, detailed paths, hashes of private low-entropy content and raw envelopes in authenticated diagnostics/recovery. Hashing private content is not anonymization. Do not add a route that exposes a whole `ProviderAttemptResult`, exception or private receipt.

Diagnostics do not change acceptance, consent, protocol dispatch, sampling, fallback, pacing or the existing retry policy. They never schedule a retry to obtain better evidence. Malformed, truncated and domain-invalid outputs remain rejected and consume their real reported usage; missing or contradictory usage keeps its conservative reservation. A diagnostic write failure cannot authorize resending an already dispatched attempt. Record the missing receipt safely and retain the attempt's spent/unknown status.

Offline inspection can compare a retained candidate against its issued schema and the existing versioned decoder. Reproducing a domain refusal additionally needs the exact validation state or a verifiable private recovery/event reference; hashes alone cannot reconstruct it. Where that state is unavailable, report only the stages actually reproduced. Never “fix” JSON, fill a choice, infer consent or apply a diagnostic replay to the live world.

## Acceptance checks for a later patch

Use isolated fixtures, not inference: malformed JSON versus an unwrapped tuple; `finish_reason=length` despite parseable JSON; missing/extra tuple items; invalid choice and nested extra fields; valid shape with a domain refusal; changed-state revalidation; a rejected primary followed by successful fallback with distinct receipts; complete and incomplete billable usage; duplicate delivery and recovery. Assert no effects for rejection, no new dispatch from diagnostics, no second settlement, bounded storage, and no private text/unknown keys in public JSON. A receipt captured from a future real failure can then answer why that attempt failed; the lost F58 raw response remains unknown.
